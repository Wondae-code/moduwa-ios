# iOS 앱 심사 준비 — 기준과 이 앱의 현재 상태 (2026-09-01)

애플 App Review Guidelines(2026-09 기준)를 읽고, **이 앱의 코드·서버를 직접 확인해** 대조했다.
"기준 목록"이 아니라 **지금 내면 무엇에 걸리는지**를 적는다.

> **한 줄 요약**: 반드시 리젝되는 것이 **4건** 남았고, 그중 **3건은 서버 라우트가 필요**하다.
> 앱만으로 오늘 처리할 수 있는 것은 **애플 로그인** 하나다.

---

## A. 지금 제출하면 **반드시 리젝**되는 것 (4건)

### A1. 계정 삭제가 앱 안에 없다 — 5.1.1(v)
계정을 만들 수 있는 앱은 **앱 안에서 계정 삭제도 제공해야 한다.** 예외가 없는 조항이고,
리젝 사유로 가장 흔하다.

- 앱: 로그아웃만 있다(프로필 편집 → 회원정보 수정). "탈퇴" 문자열이 코드에 0건.
- 서버: `auth-routes.ts` 에 삭제 라우트가 없다.
- 필요: `DELETE /v1/auth/me` + 앱의 탈퇴 화면(재확인 → 삭제 → 로그아웃 상태로).
  ⚠️ 지운 계정의 글·후기·댓글·플랜을 어떻게 할지 정해야 한다(같이 삭제 / 작성자만 익명화).

### A2. 사용자 차단이 없다 — 1.2
사용자 생성 콘텐츠가 있는 앱은 **네 가지를 모두** 갖춰야 한다:
① 유해물 필터, ② 신고 수단, ③ **가해 사용자 차단**, ④ 공개된 연락처.

- ② 신고: **오늘 완료**(게시글·후기·양쪽 댓글).
- ③ 차단: **없다**(앱·서버 모두 0건).
- ①④: B2·B3 참고.
- 필요: 서버 `POST/DELETE /v1/blocks` + 목록·상세·댓글에서 **차단한 사람의 글을 빼는 것**까지.
  차단이 목록에서 걸러지지 않으면 심사에서 "차단이 동작하지 않는다"로 잡힌다.

### A3. 애플 로그인이 없다 — 4.8
제3자 소셜 로그인(구글·카카오)을 제공하면, **동등한 조건의 로그인 수단**을 함께 제공해야 한다
(이름·이메일만 수집 / 이메일 숨기기 가능 / 광고 목적 추적 없음). 실질적으로 Sign in with Apple 이다.

- 앱: 애플 버튼 없음. 코드 주석에 이유가 적혀 있다 — 유료 멤버십이 없어 엔타이틀먼트를 켤 수
  없었다(`AuthFormControls.swift:479`). **이제 멤버십이 있으니 막힌 이유가 사라졌다.**
- 서버: `POST /v1/auth/apple` **이미 있다.**
- 필요: App ID 에 Sign in with Apple 켜기 → 엔타이틀먼트 추가 → 버튼 하나. **앱만으로 가능.**

### A4. 개인정보 처리방침이 없다 — 5.1.1(i)
**앱 안에서 쉽게 닿는 자리**와 **App Store Connect 메타데이터** 두 곳에 링크가 있어야 한다.
방침에는 수집 항목·수집 방법·이용 목적·보관/삭제 정책·동의 철회 방법이 명시돼야 한다.

- 앱: 개인정보 처리방침 항목 자체가 없다(설정 메뉴에 "서비스 이용약관" 만 있고 그것도 준비 중).
- 필요: 방침 문서(웹 URL) + 설정 메뉴에 링크. A1 의 삭제 절차도 방침에 함께 적어야 한다.

## B. 높은 확률로 지적받는 것

### B1. "준비 중" 화면 다섯 곳 — 2.1
심사는 **동작하지 않는 자리**를 미완성으로 본다. 지금 앱에 다섯 곳이 있다:

| 자리 | 지금 |
|---|---|
| 설정 → 고객센터 | "준비 중이에요" |
| 설정 → 서비스 이용약관 | "준비 중이에요" |
| 후기 작성자 팔로우 | "준비 중이에요" |
| 장소 상세 ⋯ 메뉴 | "준비 중이에요" |
| 장소 후기 화면 ⋯ 메뉴 | "준비 중이에요" |

고객센터·약관은 A4 와 함께 **실제 내용으로** 채우는 것이 맞다(둘 다 심사 필수 요소와 연결된다).
팔로우·⋯ 메뉴는 **버튼을 빼는 것**이 통과에 안전하다 — 없는 기능은 지적받지 않는다.

### B2. 유해물 필터와 운영 절차가 없다 — 1.2
신고는 접수되지만, **올라오는 것을 걸러 내는 장치**와 **신고에 대응하는 절차**가 없다.
심사에서 "신고를 받은 뒤 어떻게 처리하나"를 묻는 경우가 있다.
- 최소선: 서버에 금칙어 필터(등록 시 400) + 신고 목록을 볼 운영 화면(서버 대시보드에 붙일 수 있다).

### B3. 연락처가 앱에 공개돼 있지 않다 — 1.2
고객센터가 준비 중이라 **연락할 방법이 앱 안에 없다.** 이메일 한 줄이라도 있으면 충족된다.

### B4. 아이패드에서도 심사한다
`TARGETED_DEVICE_FAMILY = "1,2"` — 아이폰 + 아이패드다. 아이패드 레이아웃이 깨지면 리젝된다.
- `UIRequiresFullScreen = YES` 라 멀티태스킹 요구는 면제되지만 **화면 자체는 본다.**
- 지금 아이패드에서 확인한 적이 없다. 둘 중 하나를 골라야 한다:
  아이패드에서 검수하고 고치기 / `TARGETED_DEVICE_FAMILY = 1`(아이폰 전용)로 내리기.

### B5. 데이터 출처 표기가 화면에 없다 — 5.2.1 + 관광공사 라이선스
관광공사 TourAPI 는 **표출 시 출처 표시**를 요구한다(`docs/API.md` 의 라이선스 절).
앱 화면에는 출처 문구가 없다(코드 주석에만 있다). 설정 또는 장소 상세 하단에 한 줄이 필요하다.

## D. 이미 충족한 것

- **신고 수단**(1.2) — 게시글·후기·양쪽 댓글, 사유 6종 + 상세. 신고가 글을 감추지 않는다.
- **푸시**(4.5.4) — 앱 실행에 필수가 아니고, 설정에서 켜고 끌 수 있다. 광고성 발송 없음.
- **로그인 없이 둘러보기**(5.1.1) — 장소·후기·게시글 읽기는 비로그인도 된다. 쓰기에서만 묻는다.
- **최소 기능**(4.2) — 웹 재포장이 아니다(지도·추천 엔진·플랜 공동 편집·오프라인 폴백).
- **접근성** — 심사 항목은 아니지만 이 앱의 강점이고, 심사자에게도 그렇게 읽힌다.

## E. 서버에 요청할 것 (묶어서 한 번에)

1. `DELETE /v1/auth/me` — 계정 삭제. 관련 데이터 처리 방침 결정 필요(삭제 vs 익명화).
2. 차단 — `POST /v1/blocks {targetUuid}` · `DELETE /v1/blocks/:uuid` · `GET /v1/blocks`,
   그리고 **목록/상세/댓글 응답에서 차단한 사람의 것을 제외**.
3. (선택) 금칙어 필터 — 글·후기·댓글 등록 시 400.

## F. 권하는 순서

1. **애플 로그인**(A3) — 앱만으로 된다. 서버 라우트도 이미 있다.
2. **서버 요청서**(E) 전달 — 그동안 앱은 3·4를 진행.
3. **개인정보 처리방침 + 이용약관 + 고객센터 연락처**(A4·B1·B3) — 문서가 나오면 앱은 링크만 붙인다.
4. **"준비 중" 버튼 정리**(B1) — 팔로우·⋯ 메뉴 제거.
5. **아이패드 결정**(B4) — 검수하거나 아이폰 전용으로 내린다.
6. 데모 계정·App Privacy·연령 등급 작성(C) → 제출.
