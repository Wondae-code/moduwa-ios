## 요청 1. 게시글 수정 — `PATCH /v1/posts/:postId`

```jsonc
// PATCH /v1/posts/{postId}   (온 키만 갱신)
{
  "body": "고친 내용",
  "imageURLs": ["https://…"],          // 통째로 교체
  "accessFeatures": ["wheelchair"],    // 통째로 교체
  "places": [{ "contentID": "126508", "name": "불국사", "region": "경주" }]
}
```

- **권한은 삭제 라우트와 같은 규칙으로** — 본인 글만, 남의 글이면 `403` 이 아니라 **`404 not_found`**.
  이미 `DELETE` 가 그렇게 하고 있어 앱에서 분기가 하나로 끝나고, 남의 글 존재 여부도 새지 않습니다.
- **배열은 부분 병합이 아니라 통째 교체**로 부탁드립니다(플랜 저장과 같은 판단). `places` 가 오면
  `post_places` 를 지우고 순서대로 다시 넣어 주세요. 온 키만 건드리고, 없는 키는 그대로 두면 됩니다.
- 검증은 **생성과 동일**하면 충분합니다 — `missing_body`(트림 후 빈 문자열) · `body_too_long` ·
  `too_many_images` · `too_many_places` · `invalid_place`.
- `authorNm` 은 앱이 **보내지 않습니다.** 프로필 편집이 생겼으니 글을 고친다고 닉네임이 따라 바뀌지
  않는 편이 낫습니다(생성 라우트의 `update authors set nickname = …` 부수효과는 그대로 두셔도 됩니다).
- 응답은 `POST /v1/posts` 와 **같은 모양**(200) 이면 됩니다 — 앱이 그 값으로 목록 카드와 상세를
  한 번에 갱신합니다.
- 있으면 좋은 것: 응답에 `updatedAt`. 있으면 앱이 "수정됨" 을 붙일 수 있습니다. 없어도 진행합니다.

## 요청 2. 후기 신고 — `POST /v1/reviews/:reviewId/report`

**앱은 이미 만들어 두었습니다** — 사유 목록·시트·로그인 게이트가 붙어 있고, 라우트만 열리면 동작합니다.

```jsonc
// POST /v1/reviews/{reviewId}/report   (인증 필요)
{ "reason": "spam", "detail": "광고 링크가 있어요" }   // detail 은 선택, 300자 이하
```

- `reason` 은 앱이 쥔 고정 6종입니다(문구는 앱에 있고, 아래 키만 옵니다):
  `spam` · `abuse` · `falseInfo` · `privacyLeak` · `irrelevant` · `other`.
  모르는 값은 `400 invalid_reason` 으로 막아 주세요.
- 응답은 `204` 로 충분합니다. **같은 사용자가 같은 후기를 다시 신고하면 멱등하게 204** 로 —
  좋아요와 같은 판단입니다(두 번 눌렀다고 오류를 보여 줄 이유가 없습니다).
  저장은 `unique (review_id, author_id)` 에 `on conflict do update set reason=…, detail=…` 정도가 편합니다.
- 테이블 제안: `review_reports(id, review_id, author_id, reason, detail, created_at)`.
  처리(숨김·삭제)는 운영 판단이라 앱은 아무 것도 기대하지 않습니다.
- **앱은 신고해도 그 후기를 감추지 않습니다.** 곧바로 숨기면 "신고를 누르면 남의 글이 사라지는" 길이
  되고, 앱에만 숨기면 기기를 바꾸면 되살아납니다.
- ⚠️ **지금 앱은 `404` 를 "라우트가 아직 없다" 로 읽습니다**(열리기 전 상태를 사용자에게 오류로
  보여주지 않기 위해). 라우트를 여실 때 알려 주시면 그 임시 처리를 빼고, 없는 후기의 `404` 를
  "신고를 접수하지 못했어요" 로 바꾸겠습니다.

## 요청 3. `POST /v1/plans/recommend` 에 붐빔 선호 — `avoidCrowds`

시안 4/6(`958:633`)의 **"덜 붐볐으면 좋겠어요"** 체크박스를 앱에 붙였는데 실을 자리가 없습니다.
지금 앱은 **값을 보내지 않습니다** — 모르는 키가 섞이면 추천이 통째로 400 이 될 수 있어서입니다.

```jsonc
{ "region": "yeosu", "startDate": "2026-09-01", "endDate": "2026-09-02", "avoidCrowds": true }
```

- 서버는 이미 혼잡일에 `congestion.busy_penalty` 감점 / `quiet_bonus` 보너스를 줍니다.
  `avoidCrowds` 는 그 **세기를 사용자가 고르게** 하는 스위치로 보시면 됩니다 —
  `true` 면 두 가중치를 키우고(예: `recommend_weights` 에 `congestion.avoid_*` 키 추가),
  기본(`false`/미전송)은 **지금 동작 그대로** 부탁드립니다.
- `notes` 의 `no_congestion_data` 는 그대로 유지해 주세요. 앱이 그 값을 보고
  "이 지역·기간은 혼잡도 데이터가 없어 반영되지 않았어요" 를 보여줄 수 있습니다(현재 커버리지 24%).
- 필드가 열리는 즉시 앱은 한 줄로 싣습니다.

## 요청 5. 푸시 알림

받고 싶은 사건은 셋입니다 — **내 게시글에 좋아요 · 내 게시글에 댓글 · 내 플랜에 새 멤버 합류**.

### 5-1. 기기 토큰 등록·해제

```jsonc
// POST /v1/devices   (인증 필요) → 204
{ "token": "a1b2…",            // APNs 기기 토큰(hex)
  "platform": "ios",
  "environment": "production", // "sandbox" | "production"
  "bundleId": "com.waasegye.moduwa" }

// DELETE /v1/devices/{token} → 204   (로그아웃·알림 스위치 끄기에서 부릅니다)
```

- 같은 토큰 재등록은 **upsert(멱등)** 로. 앱은 앱 실행마다 등록을 시도합니다(토큰이 바뀔 수 있어서).
- ⚠️ **`environment` 를 토큰과 함께 보관해 주세요.** TestFlight·앱스토어 빌드는 production,
  Xcode 로 꽂은 빌드는 sandbox 이고, 반대쪽으로 보내면 `BadDeviceToken` 으로 **조용히** 실패합니다.
- ⚠️ 토큰은 기기·설치 단위라 재설치·기기 복원에 바뀝니다. `authors` 1 : N 으로 두시고,
  APNs 가 `410 Unregistered` 를 주면 그 행을 지워 주세요.
- 설정 화면의 알림 스위치는 **앱이 등록/해제로 표현합니다** → 서버에 사용자 설정 컬럼이 필요 없습니다.

### 5-2. 발송에 필요한 값

APNs Auth Key(`.p8`) + Key ID / **Team ID `8G2743WJL4`** / **topic = `com.waasegye.moduwa`**.
`.p8` 은 앱팀이 발급해 **이 문서·깃 밖으로** 전달합니다 — Railway 환경변수에 base64 문자열
하나로 넣는 방식을 권합니다(파일을 저장소에 두지 않게).

### 5-3. 트리거와 규칙

| 사건 | 받는 사람 | 문구(제안) | payload |
|---|---|---|---|
| 게시글 좋아요 `PUT /v1/posts/:postId/like` — **켜질 때만** | 글 작성자 | "○○님이 회원님의 글을 좋아합니다" | `type=post_like`, `postId` |
| 게시글 댓글 `POST /v1/posts/:postId/comments` | 글 작성자 | "○○님이 댓글을 남겼어요: …" | `type=post_comment`, `postId` |
| 플랜 합류 `POST /v1/plan-invites/accept` — **새로 들어온 경우만** | 소유자 + 기존 멤버(합류자 제외, 최대 10명) | "○○님이 '제주 여행'에 합류했어요" | `type=plan_member_joined`, `planId` |

- **자기 행동에는 보내지 않습니다** — 내 글에 내가 좋아요·댓글을 달았을 때.
- 플랜 합류는 `alreadyMember: true` 로 빠지는 경로(`app.ts:1848`)와
  `insert … on conflict do nothing` 이 **0행**인 경우에는 보내지 마세요 —
  초대 링크를 두 번 열면 두 번 울립니다.
- 좋아요는 껐다 켜기를 반복할 수 있으니 `(post_id, actor)` 당 **하루 1회** 정도로 묶어 주세요.
- 문구에 남의 닉네임과 댓글 본문이 들어갑니다 — 잠금화면에 그대로 보이니 **본문 인용은 40자 내외로
  잘라** 주세요.
- `aps.thread-id` 를 `post:{postId}` / `plan:{planId}` 로 주시면 iOS 가 같은 글의 알림을 묶습니다.
- **뱃지(`aps.badge`)는 넣지 마세요** — 서버가 안 읽은 수를 모르는 동안 `0` 을 보내면 뱃지가 지워지고,
  임의의 수를 보내면 실제와 어긋납니다. 5-4 가 열리면 그때 넣으면 됩니다.
- 페이로드의 `type` + 아이디만 있으면 앱이 해당 화면으로 보냅니다(초대 링크 처리와 같은 경로).
