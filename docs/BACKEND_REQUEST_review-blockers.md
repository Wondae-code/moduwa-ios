## 요청 1. 계정 삭제 — `DELETE /v1/auth/me` 🔒

```jsonc
// DELETE /v1/auth/me   (인증 필요)  → 204
```

성공하면 앱은 로컬 세션을 지우고 비로그인 상태로 돌아갑니다. 되돌리는 화면은 두지 않습니다.

### 콘텐츠 처리 — **작성자만 익명화**(앱팀·기획 결정)

지운 계정의 글·후기·댓글·플랜은 **남기고, 작성자 표시만 지웁니다.**

- 이유: 함께 쓴 대화가 통째로 사라지면 남은 사람의 화면이 깨집니다. 답글만 남은 스레드,
  멤버가 사라진 공유 플랜, 후기 수가 줄어드는 장소 — 지운 사람이 아니라 **남은 사람이** 손해를 봅니다.
- 개인정보는 남지 않습니다. 심사도 이 방식으로 통과합니다("데이터 삭제"는 개인정보를 지우는 것이지
  사용자가 만든 공개 콘텐츠를 지우는 것이 아닙니다).

**지워야 하는 것**(개인정보·접근 수단):
- `authors`: 이메일·비밀번호 해시·프로필 사진 → 삭제/`null`, 닉네임 → 고정 문구(예: `탈퇴한 사용자`)
- 소셜 신원(구글·애플·카카오 매핑) 행 **전부 삭제** — 같은 소셜로 다시 로그인하면 **새 계정**이 되어야 합니다
- 세션 토큰 전부 폐기
- **기기 토큰(`device_tokens`) 삭제** — 남으면 탈퇴한 사람의 기기로 알림이 계속 갑니다
- 개인 기록: 저장한 장소, 좋아요(글·후기)

**남기는 것**: 게시글·후기·댓글·플랜 본문과 사진, 신고 기록(운영 자료)

### 결정이 필요한 것 둘

1. **내가 소유자인 공유 플랜** — 소유자가 사라지면 플랜이 고아가 됩니다.
   제안: 멤버가 남아 있으면 **가장 먼저 합류한 편집자에게 소유권 이전**, 아무도 없으면 삭제.
2. **같은 이메일로 재가입** — 가능해야 한다고 봅니다(이메일을 지우면 자연히 가능해집니다).

### ⚠️ 애플 로그인 때문에 하나가 더 붙습니다

오늘 앱에 **Sign in with Apple** 을 붙였습니다(심사 규칙 4.8). 애플 로그인을 제공하는 앱은
**계정 삭제 시 애플 토큰 폐기 API 를 호출해야 합니다** — 앱에서는 할 수 없고 서버 몫입니다.

```
POST https://appleid.apple.com/auth/revoke
  client_id=com.waasegye.moduwa
  client_secret=<Sign in with Apple 키(.p8)로 서명한 JWT>
  token=<저장해 둔 refresh_token 또는 access_token>
  token_type_hint=refresh_token
```

- ⚠️ **APNs 키와 다른 키**입니다(용도가 Sign in with Apple 인 별도 `.p8`). 필요하면 발급해 전달합니다.
- 폐기에 쓸 토큰이 필요하므로, **애플 로그인 시 애플이 주는 refresh token 을 계정에 저장**해
  둬야 합니다. 지금은 ID 토큰만 검증하고 버리고 있어서, 그 저장부터 필요합니다.
- 애플 로그인으로 가입한 계정에만 해당합니다.

### 그리고 서버 환경변수 하나

애플 로그인이 성립하려면 `APPLE_CLIENT_IDS` 에 **번들 ID `com.waasegye.moduwa`** 가 있어야
합니다(`social-tokens.ts:116` 이 토큰의 `aud` 를 그것과 대조합니다). 지금 비어 있으면 401 입니다.

## 요청 2. 사용자 차단

### 2-0. ⚠️ 먼저 — **차단할 사람을 가리킬 값이 응답에 없습니다**

지금 글·후기·댓글의 작성자 정보는 **닉네임과 사진뿐**입니다(`authorInfo`).
닉네임으로 차단하면 동명이인이 함께 차단됩니다.

```jsonc
"authorInfo": { "nickname": "원대", "avatarUrl": "https://…", "uuid": "a3f0…" }  // ← uuid 추가
```

`isMine` 을 넣어 주신 것과 같은 성질의 값 하나입니다. 게시글·후기·양쪽 댓글 응답에 넣어 주세요
(`authors.uuid` — 이미 외부 노출용 식별자로 쓰고 있는 값입니다).

### 2-1. 라우트

```jsonc
POST   /v1/blocks   { "uuid": "a3f0…" }   🔒 → 204   // 재요청 멱등
DELETE /v1/blocks/:uuid                    🔒 → 204   // 없는 것도 204(멱등)
GET    /v1/blocks                          🔒 → { items: [{ uuid, nickname, avatarUrl }] }
```

`GET` 은 설정의 "차단한 사용자" 목록에 씁니다 — 차단은 **해제할 길이 함께 있어야** 합니다.

### 2-2. 차단이 실제로 효과가 있어야 합니다

라우트만 있고 목록이 그대로면 심사에서 "차단이 동작하지 않는다"로 잡힙니다.
**차단한 사람의 것을 응답에서 빼 주세요**:

- `GET /v1/posts`(홈·저장·장소별), `GET /v1/posts/:id/comments`
- `GET /v1/reviews`, `GET /v1/reviews/:id/comments`, `GET /v1/barrier-free/:id` 의 후기 요약·목록
- 푸시 알림 — 차단한 사람의 좋아요·댓글로는 알림이 가지 않아야 합니다

**방향**: 제안은 **단방향 + 쓰기 차단**입니다.
① 내가 차단한 사람의 콘텐츠는 내 화면에서 사라진다.
② 그 사람은 **내 글에 새 댓글을 달 수 없다**(403). 상대 화면에서 내 글이 사라지지는 않습니다.
①만 하면 차단해도 계속 댓글이 달려 알림만 막힌 상태가 됩니다.

## 요청 3. (선택) 금칙어 필터 — 1.2

심사에서 "올라오는 것을 어떻게 걸러 내나"를 묻는 경우가 있습니다. 게시글·후기·댓글 등록 시
금칙어를 400 으로 막는 것만으로도 답이 됩니다. 목록 관리가 부담이면 **신고 목록을 볼 운영 화면**
(대시보드에 한 줄)만이라도 있으면 "신고에 대응하는 절차"를 설명할 수 있습니다.

## 앱팀이 붙일 것 (라우트가 열리면)

- 계정 삭제: 설정 → 프로필 편집 → **회원정보 수정** 안(로그아웃 아래)에 "회원 탈퇴".
  되돌릴 수 없다는 안내 + 확인 한 번 → `DELETE` → 로그아웃 상태로.
- 차단: 신고 시트를 보낸 뒤 "이 사용자 차단하기"를 함께 제안, 댓글·글의 `⋯` 메뉴에 "차단",
  설정에 **차단한 사용자** 목록(해제 포함).

이 둘이 없으면 **심사에 제출할 수 없습니다**(리젝이 아니라 제출 자체가 무의미합니다).
다른 요청보다 먼저 봐 주시면 좋겠습니다. 결정이 필요한 두 가지(공유 플랜 소유권 이전, 재가입)는
