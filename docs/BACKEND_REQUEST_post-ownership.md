# 백엔드 요청 — 게시글 응답에 소유 표시 한 줄 (2026-08-31, 추가 요청)

> **처리 완료(같은 날, prod 배포)** — 목록·단건은 물론 **생성(201)·수정(PATCH) 응답에도** 실렸고,
> 댓글(`GET /v1/posts/:postId/comments`·댓글 작성 응답)에도 미리 들어갔다. 비로그인은 `false`
> (`coalesce` 로 감싸 null 이 오지 않는다 — 앱은 옵셔널로 받지 않아도 되지만, 키가 없던 시절의
> 응답을 견디려고 DTO 에서만 옵셔널로 읽고 `?? false` 로 접는다).
> 앱은 우회(`MyPostIDStore`)를 **지웠다**. 댓글의 `isMine` 은 "내 댓글 삭제" 를 붙일 때 쓴다 —
> 삭제 라우트는 아직 없다(필요해지면 요청한다).

앱팀입니다. 작은 요청 하나입니다. **게시글 응답에 "이 글이 보는 사람의 것인지"가 없어서**
앱이 우회하고 있는데, 그 우회를 지우려면 한 줄이 필요합니다.

## 지금 응답

```jsonc
// GET /v1/posts/:postId
{ "id": "6194e26…", "body": "테스트99",
  "author": "원대",
  "authorInfo": { "nickname": "원대", "avatarUrl": "https://…" },
  "likeCount": 0, "likedByMe": false, … }
```

작성자 정보가 **닉네임과 사진뿐**입니다. 보는 사람과 대조할 식별자가 없어, 상세 화면이
수정·삭제 메뉴를 띄울지 판단할 근거가 응답 안에 없습니다.

## 요청: `isMine` (또는 기존 작명에 맞는 이름)

```jsonc
{ …, "likedByMe": false, "isMine": true }
```

- `likedByMe` 와 **똑같은 성질**입니다 — 보는 사람 기준의 파생 값이고, 이미 `$VIEWER` 를
  쓰고 있으니 `POST_SELECT` 에 한 줄이면 됩니다:
  ```sql
  (p.author_id = $VIEWER) as "isMine"
  ```
- 목록(`GET /v1/posts`)과 단건(`GET /v1/posts/:postId`) **양쪽에** 실어 주시면 좋습니다.
  목록 카드에서도 쓸 자리가 생깁니다(지금은 상세에서만 씁니다).
- 비로그인은 `false` 로 오면 됩니다(`likedByMe` 와 같습니다).
- 댓글(`POST_COMMENT_SELECT`)에도 같은 값이 있으면 나중에 "내 댓글 삭제"를 붙일 때 그대로
  쓰겠습니다. **지금 당장 필요한 것은 게시글뿐입니다.**

## 앱이 지금 하고 있는 우회 (요청이 반영되면 지웁니다)

로그인 시 `GET /v1/posts?mine=true` 를 **한 번** 받아 아이디만 쥐고, 상세에서 그 목록에
있는지로 가릅니다(`MyPostIDStore`). 새로 쓴 글은 곧바로 넣고, 지운 글은 빼고, 로그아웃하면
비웁니다.

- **닉네임 비교는 쓰지 않았습니다** — 동명이인이 있으면 남의 글에 수정·삭제 메뉴가 달립니다.
  누르면 라우트가 404 로 막아 주지만, 메뉴가 보이는 것 자체가 "지울 수 있다"는 약속입니다.
- 우회의 대가: 상세를 처음 열 때 **요청이 한 번 더 늘고**(최대 5장·500건까지 훑습니다),
  그보다 오래된 글은 내 글인데도 메뉴가 안 뜹니다. 실패 방향은 안전한 쪽입니다(안 보이는 쪽).

`isMine` 이 오면 `MyPostIDStore` 를 **통째로 지우고** 한 줄 비교로 바꿉니다 —
요청 한 번, 캐시 하나, 로그아웃 시 비우는 코드가 함께 사라집니다.

## 급하지 않습니다

지금도 동작합니다. 다른 작업 사이에 여유가 있을 때 넣어 주시면 됩니다.
넣으신 뒤 알려 주시면 앱에서 우회를 지우고 배포하겠습니다.
