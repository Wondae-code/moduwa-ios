# 백엔드 요청 — 신고를 게시글·댓글까지 (2026-08-31)

앱팀입니다. 신고가 **후기에만** 있습니다(`POST /v1/reviews/:reviewId/report`).
그런데 사용자가 문제를 발견하는 자리는 후기만이 아닙니다 — 게시글과 댓글에도 같은 것이 필요합니다.
지금은 그 자리에 신고 버튼을 둘 수가 없어서, 신고할 수 없는 글이 앱의 대부분입니다.

## 지금 신고할 수 있는 것 / 없는 것

| 대상 | 라우트 | 앱 진입점 |
|---|---|---|
| 후기 | ✅ `POST /v1/reviews/:reviewId/report` | 장소 상세의 후기 줄, **후기 상세**(오늘 추가) |
| 게시글 | ❌ 없음 | — |
| 게시글 댓글 | ❌ 없음 | — |
| 후기 댓글 | ❌ 없음 | — |

사유 목록·상세(300자)·멱등 규칙은 **후기 신고와 똑같이** 쓰면 됩니다. 앱은 시트 한 벌
(`ReviewReportSheet`)을 대상만 바꿔 재사용할 계획이라, 대상이 늘어도 화면은 늘지 않습니다.

---

## 제안 A (권합니다) — 대상을 필드로 받는 라우트 하나

```jsonc
// POST /v1/reports   🔒  → 204
{ "targetType": "post",           // post | post_comment | review | review_comment
  "targetId": "6194e26…",         // 게시글은 uuid, 나머지는 정수 → 문자열로 통일
  "reason": "spam",               // 지금 후기 신고와 같은 6종
  "detail": "광고 링크가 있어요" }   // 선택, 300자
```

- **테이블도 하나**면 충분합니다: `reports(id, target_type, target_id, author_id, reason, detail, created_at)`
  + `unique (target_type, target_id, author_id)`. 신고 대상이 넷인데 테이블을 넷 두면
  운영에서 볼 곳도 넷이 됩니다.
- 기존 `POST /v1/reviews/:reviewId/report` 는 **그대로 두셔도 됩니다**(앱이 이미 쓰고 있습니다).
  내부에서 `reports` 로 넘기시면 데이터가 한곳에 모입니다.
- 모르는 `targetType` 은 `400`, 없는 대상은 `404` 로 부탁드립니다.

## 제안 B — 지금 URL 모양을 유지

```
POST /v1/posts/:postId/report                              🔒 → 204
POST /v1/posts/:postId/comments/:commentId/report          🔒 → 204
POST /v1/reviews/:reviewId/comments/:commentId/report      🔒 → 204
```

라우트 셋이 늘고 테이블을 나눌지 합칠지 따로 정해야 하지만, 기존 규칙과 모양이 같습니다.
**어느 쪽이든 앱은 상관없습니다** — 편한 쪽으로 정해 주세요.

## 공통으로 지켜 주시면 좋은 것 (후기 신고와 같게)

- **본인 것도 신고 가능**하게 열어 두거나 막으셔도 됩니다 — 앱은 어느 쪽이든 대응합니다.
  다만 막으실 경우 `403`/`400` 대신 **`204`(무시)** 가 앱에 편합니다(오류창을 띄울 이유가 없습니다).
- **같은 사람의 재신고는 멱등하게 204** (지금 후기 신고와 같음).
- **신고가 대상을 감추지 않습니다.** 앱도 감추지 않습니다 — 곧바로 숨기면 신고 버튼이 남의 글을
  지우는 도구가 됩니다(서버가 후기에서 세운 원칙 그대로).

## 앱이 할 일 (열리면)

- 게시글 상세 `⋯` 에 "신고"(내 글이면 수정·삭제 자리, 남의 글이면 신고).
- 댓글 길게 누르기 메뉴에 "신고"(내 댓글이면 수정·삭제, 남의 댓글이면 신고) — 지금 남의 댓글은
  길게 눌러도 아무 것도 없습니다.
- 시트는 `ReviewReportSheet` 를 `ReportSheet(target:)` 으로 일반화해 그대로 씁니다.

## 급하지 않습니다

다만 **테스터에게 앱을 열기 전에는 있는 편이 낫습니다** — 신고할 수 없는 커뮤니티는 앱 심사에서도
지적받는 항목입니다(사용자 생성 콘텐츠가 있는 앱은 신고 수단을 요구합니다).
